Multichamber brings OpenCode, Claude Code and Codex conversations into one workspace. It builds on the original OpenChamber project and the native Claude Code work in pocharlies-org/openchamber, with credit to their contributors.

## App

### New
- **Sessions:** open native Claude Code and Codex histories, continue conversations, follow tools as they run, and answer approvals and questions alongside OpenCode sessions.
- **Settings:** choose a default engine and separate model, reasoning and permission defaults. Check versions for all three engines; supported native updates require confirmation.
- Codex: open child conversations from task cards and read messages sent between agents without showing the parent as a subtask.

### Improvements
- Chat: steer messages, queued sends, goals and shared project context use the session's own engine. Goals require a configured progress checker.
- Sidebar: filter by engine and identify session ownership independently of the model provider, with compact rows that keep real branch details.
- Codex: usage and permission controls reflect the native session. New sessions default to full access; existing sessions keep their native permissions.

### Fixes
- Codex: prompts stay before their replies after paging or reloading, and child conversations with assistant-only histories no longer open as empty panels.
- Context: Claude and Codex sessions no longer show OpenCode's MCP and skill counts or offer switches for its servers.
- Settings: native selectors show readable labels when closed, and unavailable catalogs or failed version checks stay visible as failures.

### Misc
- Multichamber has its own branding, package names, installation identity and fork release feed. App updates and native-engine updates remain separate; shared services are not restarted automatically.
- This release targets the web/server, Windows and Linux distributions. macOS, iOS and Android artifacts are excluded from this publication; the fork does not ship a VS Code extension.
- Engine limits remain explicit: arbitrary shell messages, session moves, revert, turn diffs and side generation are OpenCode-only. Codex cannot fork at arbitrary message boundaries.
